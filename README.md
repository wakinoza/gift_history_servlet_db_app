# 頂き物管理 Webアプリケーション - Security Update Edition
本プロジェクトは、以前公開した「Servlet/JSP 頂き物管理アプリ（DB対応版）」に、セキュリティとDockerを導入した、包括的セキュリティアップデート版です。

単に機能を実装するだけでなく、「安全にデータを守り、かつ環境に依存せず動作する」という実務的な信頼性を追求しました。

## 🛡️ 本アップデートでの主なセキュリティ実装
情報処理推進機構（IPA）の『安全なウェブサイトの作り方』を指針とし、以下の対策を講じています。

1. 脆弱性の根本対策
- SQLインジェクション対策: すべてのDB操作でプリペアドステートメントを徹底。さらにJDBC接続にて useServerPrepStmts=true を強制し、サーバー側での安全な実行を担保。

- XSS (Cross-Site Scripting) 対策: JSP出力における <c:out> の徹底。hiddenフィールドやエラーメッセージも含め、スクリプト注入の隙を排除しました。

- CSRF (Cross-Site Request Forgery) 対策: 重要な操作（新規登録など）においてトークンを発行・照合。外部サイトからの意図しない操作を遮断します。

2. 認証・認可およびセッション管理
- パスワードのハッシュ化: BCrypt を採用。データベースに平文のパスワードを保存せず、万が一のデータ流出時もアカウントを保護します。

- 不適切な認証（強制ブラウジング）への対策: Filter クラスによるアクセス制御を実装。未ログイン状態で /Main 等の内部URLに直接アクセスしても、自動的にログイン画面へリダイレクトされる仕組みを構築しました。

- セッションの安全な管理: ログイン成功時にセッションIDを再発行（固定化攻撃対策）し、各種セキュリティヘッダ（X-Frame-Options, X-Content-Type-Options: nosniff 等）を付与。

3. インフラ・構成管理のモダン化
- Dockerによる環境構築 (IaC): MySQL 8.4 / Tomcat 10 (JDK 21) のマルチコンテナ構成。docker-compose 一発で誰でも同じ環境が即座に構築可能です。

- 機密情報の完全分離: .env ファイルと JNDI を組み合わせ、DBパスワード等の機密情報をソースコード（Git管理下）から完全に排除しました。

## 🚀 起動手順
Dockerがインストールされた環境であれば、以下の手順で動作確認が可能です。

1. リポジトリをクローン

```Bash
git clone https://github.com/wakinoza/gift_history_servlet_db_app
cd　gift_history_servlet_db_app
```

2. 環境変数の準備
.env.example をコピーして .env を作成し、必要な値を設定してください。
```Bash
cp .env.example .env
```

3. コンテナの起動
```bash
docker compose up -d --build
```

4. アクセス ブラウザで 「http://localhost:8080/gift/index.jsp」 にアクセスしてください。

以下の情報を入力すると、ログイン可能です。

ユーザー名：yamada
パスワード：yamada_password

## 💡 開発を通じて得られた学び
今回のアップデートで最も印象的だったのは、「不適切な認証」という脆弱性への直面です。

JSPファイルを WEB-INF 内に隠すだけでは不十分で、サーブレットURLを直接入力（強制ブラウジング）することでログインを回避できてしまう問題に気づきました。これを Filter による網羅的なアクセス制御で解決した過程で、「セキュリティは、知識がないと意図せずとも容易に穴が開くものである」という現実を痛感しました。

「たまたま公開前に気づけてよかった」で終わらせず、常に最新の脆弱性情報にアンテナを張り、アップデートを怠らない習慣を身につけたいと強く実感しています。
